# Android-приложение «ГСК Родник»: сборка, push и подпись

Приложение — это та же PWA жителя (`apps/pwa`), упакованная в Android через **Capacitor**. Страницы лежат внутри APK, данные берутся с вашего сервера по HTTPS. Нативные возможности: безопасное хранение токена (Android Keystore), push через FCM, кнопка «Назад», камера для фото счётчика, обновление из приложения.

| Параметр | Значение |
|---|---|
| Пакет (applicationId) | `ru.gskrodnik.app` |
| Минимальная версия Android | 7.0 (API 24) |
| Проект | `apps/pwa/android` |
| Версия | `apps/pwa/android/version.properties` |

---

## 1. Что нужно установить на компьютер для сборки

1. **Node.js 22+** (уже есть).
2. **JDK 21** (Microsoft OpenJDK или Temurin).
3. **Android SDK** — проще всего поставить Android Studio; нужны Platform **36** и Build-Tools **36.0.0**.
4. Переменные окружения (PowerShell, на сеанс):

```powershell
$env:JAVA_HOME    = "C:\Users\<вы>\.jdks\ms-21.0.12.1"
$env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\Sdk"
$env:Path = "$env:JAVA_HOME\bin;" + $env:Path
```

Чтобы не вводить каждый раз, задайте `JAVA_HOME` и `ANDROID_HOME` в «Переменные среды» Windows.

## 2. Firebase: push-уведомления (FCM)

Нужны **два разных файла**. Не путайте.

### 2.1. `google-services.json` — для приложения (Android)
1. Откройте <https://console.firebase.google.com> → **Добавить проект** (аналитику Google можно отключить).
2. В проекте: **Добавить приложение → Android**. Имя пакета: `ru.gskrodnik.app`. Остальные поля можно пропустить.
3. Скачайте `google-services.json` и положите в:
   `apps/pwa/android/app/google-services.json`
   (файл в git не попадает — он в `.gitignore`).

Без этого файла приложение соберётся, но push работать **не будет** (Gradle напишет в лог «google-services.json not found»).

### 2.2. Ключ сервисного аккаунта — для сервера
1. Firebase → ⚙ **Параметры проекта → Cloud Messaging**: убедитесь, что включён **Firebase Cloud Messaging API (V1)**.
2. **Параметры проекта → Сервисные аккаунты → Создать новый закрытый ключ** — скачается JSON.
3. Положите файл **на сервер** вне каталога проекта, например `/etc/gsk/fcm-service-account.json`:

```bash
sudo install -d -m 750 -o gsk -g gsk /etc/gsk
sudo install -m 600 -o gsk -g gsk fcm-service-account.json /etc/gsk/fcm-service-account.json
```

4. В `.env` сервера (`apps/api/.env`) задайте:

```
FCM_SERVICE_ACCOUNT_FILE=/etc/gsk/fcm-service-account.json
PUSH_DRY_RUN=0
```

5. Перезапустите API (`sudo systemctl restart gsk-api`). В портале **Настройки → Напоминания должникам** должно появиться «Android (FCM): подключён».

> Этот JSON даёт право рассылать уведомления от имени вашего проекта. Никогда не кладите его в git, чат или на публичный ресурс. Если он утёк — удалите ключ в Firebase и создайте новый.

## 3. Адрес сервера и CORS

Приложение лежит внутри APK, поэтому адрес API должен быть абсолютным.

1. Скопируйте `apps/pwa/.env.android.example` в `apps/pwa/.env.android` и впишите адрес боевого сервера:

```
VITE_API_BASE=https://rodnik.ваш-домен.ru
```

2. На сервере в `apps/api/.env` в `CORS_ORIGINS` обязательно добавьте источник приложения **`https://localhost`**:

```
CORS_ORIGINS=https://rodnik.ваш-домен.ru,https://localhost
```

Без этого приложение будет открываться, но все запросы к серверу будут блокироваться браузерным движком (CORS).

Приложению разрешён **только HTTPS** (открытый HTTP заблокирован настройкой сети Android).

## 4. Ключ подписи (делается один раз)

Каждое обновление должно быть подписано **тем же ключом**, что и первая установка. Потеряете ключ — жители не смогут обновиться, придётся удалять и ставить приложение заново.

```powershell
keytool -genkeypair -v -storetype PKCS12 `
  -keystore G:\secure\gsk-rodnik-release.jks `
  -alias gsk-rodnik -keyalg RSA -keysize 2048 -validity 10000
```

- Храните `.jks` **вне репозитория** (например, `G:\secure\`) и **сделайте копию в надёжное место** (например, PBS / зашифрованный архив). Пароли храните в менеджере паролей.
- Создайте файл `apps/pwa/android/keystore.properties` (в git не попадает):

```properties
storeFile=G:/secure/gsk-rodnik-release.jks
storePassword=ПАРОЛЬ_ХРАНИЛИЩА
keyAlias=gsk-rodnik
keyPassword=ПАРОЛЬ_КЛЮЧА
```

(В пути используйте прямые слэши `/`.)

## 5. Версия

Перед каждой сборкой, которую вы выпускаете, увеличьте номер в `apps/pwa/android/version.properties`:

```properties
VERSION_CODE=2
VERSION_NAME=1.0.1
```

- `VERSION_CODE` — целое число, **всегда больше предыдущего**. Именно по нему приложение понимает, что вышла новая версия.
- Это же значение вы вводите в портале при загрузке APK («Код версии»).
- `VERSION_NAME` — версия для людей (1.0.1). Она попадает в **имя файла APK** (`gsk-rodnik-1.0.1.apk`) и показывается в приложении: **Профиль → Приложение → «Версия приложения: 1.0.1 (сборка 2)»**.
- **Правило проекта:** при любом исправлении или новой функции версию поднимают всегда (`VERSION_CODE` +1, `VERSION_NAME` по смыслу: исправление 1.0.1 → 1.0.2, новая функция 1.0.2 → 1.1.0). Версия задаётся только в `version.properties`: имя файла, приложение и профиль берут её оттуда (после изменения запустите `npm.cmd run android:web`).

## 6. Сборка

Из каталога `apps/pwa` (с настроенными `JAVA_HOME` и `ANDROID_HOME`):

```powershell
# Отладочная сборка (подписана отладочным ключом, для проверки на своём телефоне)
npm run android:debug
# → android\app\build\outputs\apk\debug\gsk-rodnik-<версия>-debug.apk

# Релиз (подписывается вашим ключом из keystore.properties)
npm run android:release
# → android\app\build\outputs\apk\release\gsk-rodnik-<версия>.apk
```

Команды сами собирают веб-часть (`vite build --mode android`), синхронизируют её в Android-проект и запускают Gradle. Первый запуск скачивает Gradle и библиотеки (несколько минут).

Проверка подписи релиза:

```powershell
& "$env:ANDROID_HOME\build-tools\36.0.0\apksigner.bat" verify --verbose android\app\build\outputs\apk\release\gsk-rodnik-<версия>.apk
```

Если `keystore.properties` нет, релиз соберётся **неподписанным** (`gsk-rodnik-<версия>-unsigned.apk`) — такой файл установить нельзя.

Проверка на телефоне по кабелю (включите «Отладку по USB»):

```powershell
& "$env:ANDROID_HOME\platform-tools\adb.exe" install -r android\app\build\outputs\apk\release\gsk-rodnik-<версия>.apk
```

---

### Проверка на эмуляторе с локальным сервером (для разработки)

Эмулятор видит ваш компьютер по адресу `10.0.2.2`. Для такой проверки (только debug-сборка):

```powershell
# 1. apps/pwa/.env.android:   VITE_API_BASE=http://10.0.2.2:3000
# 2. apps/api/.env:           CORS_ORIGINS=...,http://localhost      (и перезапустить API)
$env:CAP_DEV = '1'            # страницы приложения по http://localhost, HTTP к 10.0.2.2 разрешён
npm run android:debug
& "$env:ANDROID_HOME\platform-tools\adb.exe" install -r android\app\build\outputs\apk\debug\gsk-rodnik-<версия>-debug.apk
```

`CAP_DEV` действует только на время вашего сеанса PowerShell и в релиз не попадает: боевые сборки всегда используют HTTPS, а разрешение на HTTP к `10.0.2.2` лежит в `android/app/src/debug/` и есть только в debug-варианте.

## 7. Выпуск жителям

1. Откройте портал → **Приложение** → «Новая версия».
2. Укажите версию (`VERSION_NAME`), код (`VERSION_CODE`), описание «Что нового», выберите `gsk-rodnik-<версия>.apk` → **Загрузить**.
3. Портал проверит, что это настоящий APK и что код больше предыдущего.
4. (Необязательно) нажмите **Оповестить** — жителям придёт push о новой версии.

**Первая установка у жителя:** в личном кабинете PWA (раздел «Профиль → Приложение») есть кнопка «Скачать для Android». Файл скачивается только после входа. Телефон попросит разрешить установку из этого источника (браузера) — это обычное разрешение Android для APK не из Google Play.

**Обновление:** при запуске приложение спрашивает сервер о новой версии. Если она есть — показывает окно «Доступна новая версия» с описанием и кнопками **Скачать / Позже**. Кнопка «Позже» прячет окно на сутки, а в профиле остаётся отметка и кнопка обновления.

## 8. Как устроена безопасность

- **Токен входа** хранится в **Android Keystore** (шифрованное хранилище, ключ нельзя извлечь с устройства), а не в обычной памяти приложения.
- Резервное копирование Android выключено (`allowBackup=false`) — данные приложения не уходят в облачные бэкапы.
- Только HTTPS; фото и данные не кэшируются на диске приложением.
- При выходе из аккаунта устройство **отвязывается от push** на сервере.
- Если пользователь заблокирован или сессия отозвана в портале — приложение при следующем запросе выходит из аккаунта.
- Файл APK скачивается только авторизованными (подписанная ссылка на 10 минут).

## 9. Если что-то не работает

| Симптом | Причина и решение |
|---|---|
| Белый экран / «нет связи» | Неверный `VITE_API_BASE` или в `CORS_ORIGINS` нет `https://localhost`. Пересоберите после правки `.env.android`. |
| Push не приходят | Нет `google-services.json` при сборке; не задан `FCM_SERVICE_ACCOUNT_FILE`; `PUSH_DRY_RUN=1`; у жителя выключен push в профиле или запрещены уведомления в Android. Телефоны без Google-сервисов (часть Huawei) FCM не поддерживают. |
| «Приложение не установлено» | Релиз неподписан или подписан **другим ключом**, чем установленная версия. Удалите старую или подпишите тем же ключом. |
| «Версия не новее» при загрузке в портал | `VERSION_CODE` не увеличен. |
| Жителям не предлагает обновление | `VERSION_CODE` в APK не меньше загруженной версии, либо сервер недоступен. |
| Ошибка Gradle `SDK location not found` | Не задан `ANDROID_HOME`; либо создайте `android/local.properties` со строкой `sdk.dir=C\:\\Users\\вы\\AppData\\Local\\Android\\Sdk`. |
| Нужно посмотреть логи | Подключите телефон по USB: `adb logcat` (в релизе логирование приложения отключено). |

## Сборка в Android Studio: сначала веб-часть

Android Studio сама **не пересобирает интерфейс**: она берёт готовые файлы из `apps/pwa/android/app/src/main/assets/public`. Если их не обновить, в приложение попадёт старая сборка (например, с адресом сервера из прошлой проверки на эмуляторе: симптом — приложение «висит» на кнопке «Войти», а на сервере нет запросов с телефона).

Перед каждой сборкой в Studio выполняйте в PowerShell:

```powershell
cd apps\pwa
# для проверки на тестовом сервере без TLS (только debug):
$env:CAP_DEV = '1'
npm run android:web
```

Затем в Studio: **Build Variants → debug** (релиз разрешает только HTTPS), Sync Project with Gradle Files, Clean Project, Run. Проверка, что в сборку попал нужный адрес:

```powershell
Select-String -Path android\app\src\main\assets\public\assets\index-*.js -Pattern "ВАШ_АДРЕС" -List
```

Для боевой сборки `CAP_DEV` не задаётся (`Remove-Item Env:CAP_DEV`), в `.env.android` указывается `https://…`, вариант — **release**.

## Обновление приложения прямо из приложения

Когда в портале («Приложение») загружена версия с большим `VERSION_CODE`, у жителя в приложении появляется баннер «Доступна новая версия» (и такая же кнопка в Профиле). Нажатие **«Скачать и установить»**:

1. приложение получает у сервера подписанную ссылку на 10 минут (только для вошедшего пользователя; без авторизации APK не отдаётся);
2. скачивает файл внутрь приложения (с процентами), **проверяет контрольную сумму SHA-256** и при несовпадении удаляет файл;
3. открывает системное окно «Обновить это приложение?» — достаточно нажать «Обновить».

При первом обновлении Android один раз попросит разрешить **установку из этого приложения** (откроется настройка, включите переключатель и вернитесь назад; кнопка станет «Установить»). Android принимает обновление только если APK подписан **тем же ключом**, что и установленное приложение, поэтому релизы всегда подписывайте одним и тем же keystore.

Устройство: плагин `android/app/src/main/java/ru/gskrodnik/app/ApkInstallerPlugin.java` (HTTPS обязателен; HTTP разрешён только в debug-сборке), разрешение `REQUEST_INSTALL_PACKAGES` в манифесте. Кнопка **«Проверить обновления»** в Профиле показывает ответ сервера (какая версия на сервере и какая у вас).

## Безопасность приложения (кратко)

* **Установка обновления**: перед запуском установщика приложение проверяет, что файл — это «ГСК Родник» (тот же пакет), версия выше установленной и подписан **тем же ключом**; иначе файл удаляется и установка отменяется.
* **Релиз только из «чистой» веб-части**: если перед сборкой в Android Studio выполняли `cap sync` с `CAP_DEV=1`, сборка `release` остановится с пояснением (`verifyReleaseConfig`). Выполните `Remove-Item Env:CAP_DEV; npm.cmd run android:web`.
* **CSP**: в Android-сборке в `index.html` добавляется политика безопасности контента (скрипты только свои, запросы только к вашему серверу API из `.env.android`).
