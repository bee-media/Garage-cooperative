# ГСК «Родник» — система управления. Техническое задание v1

Статус: черновик, составлен по ответам заказчика. Пункты «⚠ допущение» подлежат подтверждению.

## 1. Состав системы

| Компонент | Технологии | Пользователи |
|---|---|---|
| API (`apps/api`) | Node.js LTS, NestJS, TypeScript, PostgreSQL 16 | все клиенты |
| Веб-портал (`apps/admin`) | React + Vite + TS, дизайн Deep Ocean (светлая/тёмная тема) | председатель, правление, бухгалтер, электрик |
| PWA (`apps/pwa`) | React + Vite + TS, mobile-first, Deep Ocean | жители (iOS и временно Android) |
| Android (`apps/pwa` + Capacitor) | Capacitor, APK собирает заказчик своим ключом | жители |
| Общий код (`packages/shared`) | типы, валидаторы телефона/пароля, API-клиент | все |

Один репозиторий (monorepo, npm workspaces), деплой через приватный GitLab CI на тестовый и боевой серверы.

## 2. Инфраструктура

- Debian, **systemd-сервисы без Docker**: `gsk-api.service` (порт на 127.0.0.1).
- Снаружи: **Nginx Proxy Manager** (TLS, домены настраивает заказчик) → проксирует на API и раздаёт статику порталов.
- Два окружения: `test` и `prod`, отдельные БД, `.env`, ключи.
- Бэкапы: PBS на стороне заказчика. Мы даём скрипт `pg_dump` + архив каталога файлов.
- Автодеплой: GitLab CI (job `deploy:test` по ветке `develop`, `deploy:prod` по тегу/`main` с ручным подтверждением), доставка по SSH, миграции БД при деплое. Инструкция — в конце реализации.
- Время: хранение в UTC, показ и логи **Europe/Moscow (MSK, UTC+3)**.

## 3. Роли и права

Роли **настраиваются администратором**: матрица «роль × право». Системные роли по умолчанию:
`Администратор` (всё), `Председатель`, `Бухгалтер`, `Член правления`, `Электрик`, `Житель`.

Права (гранулярные): users.view/create/edit/delete, passwords.issue, garages.*, debts.view, payments.create/edit/revoke, charges.create, meters.accept, news.create/edit/hide/delete, ads.moderate/edit/delete, schedule.edit, contacts.edit, map.view/edit/marks/poles, audit.view, roles.manage, app_release.upload, import_export, settings.
Доступ жителей к карте — отдельное право, включается админом.

## 4. Жители, гаражи, вход

- Логин = телефон `909-111-22-77`: маска ввода, только цифры, 10 цифр; в БД хранится `9091112277`.
- Пароль выдаёт только администратор: **10 символов**, верхний+нижний регистр + цифры, без похожих (`0 O o 1 l I`). Показывается крупно в окне + QR на PWA-портал (⚠ см. п. 11, QR без пароля либо с одноразовым токеном).
- Пользователь пароль **не меняет**; смена/сброс — только через админа.
- Блокировка: **5 неудачных попыток** → блокировка, снимает админ. Плюс rate-limit по IP.
- Активные сессии: список устройств, выход со всех/с выбранного, админ может завершить сессии.
- При первом входе — обязательное согласие на обработку ПДн (фиксируется дата/версия). На портале — плашка о cookies.
- В профиле: телефон, email (необязателен), гаражи, долг (₽), переключатель push.
- Гараж: номер (просто число/строка), площадь, год, особые отметки, льгота (визуальная метка в списках и карточках), статус (активен/архив), **история владельцев**.
- Связь M:N: у гаража несколько владельцев, у человека до ~10 гаражей. Долг считается на гараж.
- Удаление гаража = архивация с сохранением истории.
- Массовое создание гаражей: «от N до M».

## 5. Финансы

- Два вида начислений: **электроэнергия** и **членские взносы**. Вносит бухгалтер вручную.
- Взносы: настраиваемые тарифы, период квартал/год, льготы (ряд гаражей — льготные).
- Пеня: настраиваемая (⚠ уточнить формулу).
- Оплата вносится админом/бухгалтером: частичные платежи, авансы, привязка к периоду/виду, кто внёс — в логе.
- Квитанция/чек: шаблон настраивается админом; отправка на email и печать (PDF).
- Статусы гаража: зелёный — долга нет, оранжевый — не оплачена любая категория, красный — не оплачены обе. Рядом сумма и телефон(ы).
- Карточка гаража: полный лог начислений/оплат, объявления, показания, владельцы, пометки на карте.
- Экспорт долгов, платежей, пользователей в Excel; импорт пользователей/гаражей/долгов/начислений из Excel.

### Уточнения (ответы заказчика, раунд 2)
- Льгота — **процент скидки** на взнос (настраивается на гараже/владельце).
- Пеня — параметры задаёт бухгалтер в настройках.
- Членский взнос — единая сумма за гараж (без зависимости от площади).
- Электроэнергия: бухгалтер задаёт тариф (₽/кВт·ч); при приёме показаний система считает `расход = новое − предыдущее`, `начисление = расход × тариф`, разница ставится к оплате жителю. Бухгалтер может скорректировать.
- Квитанции/чеки и импорт/экспорт Excel — **этап 2** вместе с картой.
- Автоархив объявлений — 30 дней.
- QR при выдаче пароля — только ссылка на PWA с подстановкой номера; пароль показывается текстом крупно.
- Телефон в объявлении виден всем авторизованным.
- Пароль и сброс — только админ; email — для уведомлений/чеков.
- Гараж с несколькими владельцами: у каждого свой логин, долг общий на гараж.

## 6. Показания электросчётчика

- Передача в любое время; дата-время берётся с телефона (MSK), значение цифрами, **минимум 2 фото**, сжатие на устройстве, комментарий.
- Перед первой съёмкой — предупреждение «чёткое фото, видны цифры и пломба» (один раз).
- История, карточка показания с фото, «принято» + кто принял (любой член правления, логируется).
- Фото отдаются только авторизованным (проверка прав на каждый запрос).

## 7. Новости

- Пагинация по 5, новые сверху, поиск, закреплённые, вложения/фото.
- Админ: создать/редактировать, **снять** (скрыть, можно вернуть), удалить.
- Push при публикации. Отметка прочтения: у админа счётчик и список «кто прочитал» (⚠ допущение).

## 8. Доска объявлений

- Продажа/аренда, номер гаража (в т.ч. чужого), телефон автора, цена в ₽, до 5 фото, полноэкранный просмотр.
- Модерация: пока не одобрено — не видно другим. Отклонение с причиной + уведомление автору. Правка автором → снова на модерацию.
- Автор отправляет в архив; автоархив через N дней (настройка). Жалоба на объявление.
- **Телефон в объявлении виден другим** по требованию из первоначального ТЗ (в ответе 37 вы указали «не должен видеть чужой номер» — ⚠ см. вопросы).

## 9. Расписание и контакты

Расписание правления структурировано (дни недели, часы, исключения), контакты (должность, ФИО, телефон) — только после авторизации, тап по номеру запускает набор `tel:`.

## 10. Push

- Только: новость правления; напоминание должнику **раз в месяц, 9:00–18:00 MSK**; принятие показаний; решение по объявлению. Переключатель в профиле.
- Android: FCM (ключ создаёт заказчик, инструкция — в конце). PWA: Web Push (VAPID), на iOS только после установки на экран.

## 11. Обновление Android-приложения

Админ загружает APK и описание в портале. В приложении появляется диалог «Скачать / Позже» и постоянная отметка о доступном обновлении. Скачивание — только авторизованным. APK доступен и в ЛК PWA.

## 12. Карта ГСК (Этап 2)

SVG-редактор на подложке схемы: инструмент «ряд» (начало, конец, количество, нумерация), боксы привязаны к гаражам, цвет = статус долга, клик → карточка гаража. Пометки (напр. «нет света») с категорией, фото, комментарием, закрытие. Опоры освещения: номер, фото, комментарий, счётчик. Экспорт/печать в PDF. Доступ жителям — по праву.

## 13. Аудит-лог

Все действия админов и жителей, вход/неудачные входы, изменения «было → стало», IP/устройство, время MSK. Хранение 3 года, фильтры (пользователь, дата, тип, объект). Только добавление, без редактирования.

## 14. Дашборд

Сумма долга по видам, число должников, динамика оплат, не сдавшие показания, очередь модерации, ожидающие приёма показания.

## 15. Безопасность

argon2id; JWT 15 мин + refresh с ротацией и хранением хэша; админы — httpOnly cookie + CSRF + **TOTP 2FA**; RBAC на сервере, защита от IDOR; helmet/CSP; валидация DTO; параметризованные запросы; проверка загружаемых файлов по сигнатуре, удаление EXIF, лимиты; файлы вне webroot; неизменяемый аудит; приложения не от root; ufw + fail2ban; согласие на ПДн (152-ФЗ), политика конфиденциальности и соглашение на русском.

3. Квитанции/чеки с шаблонами, импорт/экспорт Excel, доработки.
