# Аудит безопасности и багов (16.10.2026)

Проверены все модули API (авторизация, роли, файлы, финансы, показания, новости, объявления, push, релизы, карта, Excel, квитанции, почта), портал и PWA (XSS, хранение токенов, service worker), конфигурация nginx/CSP, зависимости.

**Не найдено:** SQL-инъекций (весь доступ к БД через Prisma; единственный сырой запрос — `SELECT 1` и блокировка без пользовательских данных), `innerHTML`/`dangerouslySetInnerHTML`, выполнения команд ОС, обхода пути при выдаче файлов (`absPath` проверяет корень), хранения токенов в `localStorage`, кэширования API в service worker.

## Исправлено

| # | Серьёзность | Проблема | Исправление |
|---|---|---|---|
| 1 | **Высокая** | Повышение привилегий: держатель `passwords.issue` мог выдать пароль администратору (и сбросить ему 2FA), держатель `users.edit` — назначить роль администратора | `common/hierarchy.ts`: управлять пользователем и назначать роль можно только если права роли ⊆ своих; действия над собой (пароль, блокировка, удаление, сброс 2FA, смена роли) запрещены |
| 2 | **Высокая** | Перебор пароля пачкой параллельных запросов обходил блокировку после 5 попыток (счётчик не атомарный) | `failedAttempts: { increment: 1 }` в БД; то же для кода 2FA |
| 3 | Средняя | SSRF через подписку Web Push: сервер слал запросы на любой `https://`-адрес из подписки | Разрешены только домены push-сервисов Google, Mozilla, Apple, Microsoft |

| 6 | Средняя | Двойной клик / два бухгалтера: массовый взнос и пеня создавали дубликаты начислений | Блокировка `pg_advisory_xact_lock` + выполнение в транзакции |
| 7 | Средняя | Гонка: правка показания в момент приёма меняла значение после начисления | Условие `status = PENDING` в самом запросе обновления |
| 8 | Низкая | Одно фото можно было привязать к двум показаниям/объявлениям/новостям параллельными запросами | Уникальный индекс по `fileId` (миграция `photo_file_unique`) |
| 9 | Низкая | Фото скрытых новостей были доступны всем жителям | Только правлению |

| 11 | Низкая | В журнал попадало всё, что введено в поле телефона при неудачном входе (часто — пароль) | Пишется только нормализованный номер |

| 14 | Низкая | В production сервер мог стартовать со слабыми `JWT_ACCESS_SECRET` / `TOTP_ENC_KEY` | Проверка при запуске (32+ символов, не «change-me») |

Тесты: `npm test -w @gsk/api` (SSRF-фильтр, zip, TOTP). Сценарии 1, 2, 6, 11, 12 проверены интеграционным скриптом на живой БД.

## Известные остаточные риски (приняты)

* **Блокировка учётной записи — это и защита, и способ помешать работе:** зная телефон, можно заблокировать жителя пятью неверными попытками (требование заказчика: разблокирует администратор). Троттлинг входа — 10 запросов в минуту с IP.
* **«Сироты» (загруженные, но не привязанные фото)** удаляются автоматически: раз в час файлы старше 24 часов без привязки к показанию, объявлению, новости, карте или релизу стираются с диска и из БД, а также файлы на диске без записи в БД (событие `files.purge_orphans` в журнале). Лимит загрузок — 60 в минуту с IP и (с версии 1.3.3) суточная квота на пользователя.
* **Загрузка APK и xlsx идёт в память** (лимиты 120 МБ / 3 МБ, только для сотрудников с правами).
* **Зависимости (`npm audit --omit=dev`)**: `react-router` (open redirect в `<Link>` с недоверенным адресом — у нас все пути фиксированные), `exceljs → uuid` (v3/v5 с буфером — не используется), `prisma CLI → deepmerge-ts` (только инструмент миграций, не обрабатывает пользовательский ввод). Обновление требует мажорных версий — планово.
* **Реальные FCM/SMTP и боевая инфраструктура** не проверялись.
* **Корректность `TRUST_PROXY_HOPS`:** при неверном числе прокси подмена `X-Forwarded-For` ослабляет ограничение по IP. На сервере (NPM → nginx → API) значение 2.

# Повторный аудит: API, PWA, Android (16.10.2026, версия приложения 1.1.1)

* **Матрица прав** (`test/integration/rbac-matrix.cjs`): каждый маршрут вызывается без входа и от имени ролей «Житель», «Электрик», «Член правления», «Бухгалтер», «Председатель»; сверяется с `@RequirePermissions`. 151 маршрут, 671 проверка, нарушений 0 (без входа везде 401, без права везде 403, 4 публичных маршрута: вход, 2FA, refresh, health).
* **Доступ к чужим данным** (`test/integration/idor.cjs`): два жителя; 30 проверок (чужие показания, фото счётчика, объявления, скрытые новости, долги, сессии, профили, подписанные ссылки, обход пути, заблокированный пользователь с живым токеном) — все пройдены.
* Юнит-тесты (`npm test -w @gsk/api`): TOTP, фильтр push-адресов, защита от zip-бомбы, слияние DTO.

## Исправлено

| # | Область | Серьёзность | Проблема | Исправление |
|---|---|---|---|---|
| 1 | Android | **Средняя** | Нативный плагин ставил любой скачанный файл, если совпала контрольная сумма из того же ответа сервера (скомпрометированный сервер или внедрённый в WebView код мог подсунуть чужой APK) | Перед установкой проверяется: тот же пакет, версия выше установленной и **подпись тем же ключом** (Android в любом случае не примет обновление с другим ключом, теперь это отсекается заранее и с понятным сообщением) |
| 2 | Android | **Средняя** | В приложении не было политики безопасности контента (у PWA она приходит заголовком nginx) | Метатег CSP в Android-сборке: скрипты только свои, запросы только к своему серверу API |
| 3 | Android | Средняя | Релиз можно было собрать из «отладочной» веб-части (`CAP_DEV=1`: HTTP-схема, mixed content, отладка WebView) | Задача `verifyReleaseConfig`: релиз не собирается, если в assets отладочная конфигурация |
| 4 | API | Средняя | Подписки Web Push, сохранённые до введения фильтра адресов, всё ещё использовались при отправке (SSRF) | Адрес проверяется и при отправке; недопустимые подписки удаляются |
| 5 | API | Низкая | Число push-устройств пользователя не ограничено | Не более 10, старые удаляются |
| 6 | PWA | Низкая | Service worker и нативное приложение переходили по адресу из push-уведомления без проверки (`//хост`) | Только пути внутри приложения |

## Что проверено и в порядке

* Манифест Android: `allowBackup=false`, `usesCleartextTraffic=false`, единственная экспортируемая активность — главная; экспортируемые получатели библиотек защищены системными разрешениями; релиз не отладочный; HTTP разрешён только в debug и только для тестового адреса.
* Токены: access только в памяти, refresh — httpOnly cookie (браузер) / Android Keystore (приложение); в `localStorage` ничего секретного.
* Файлы: изображения перекодируются, APK отдаётся только вошедшему по подписанной ссылке на 10 минут, привязанной к сессии (после выхода ссылка не действует).
* Деплой: ключ CI — принудительная команда, проверка идентификатора релиза по шаблону, sudo только на перезапуск `gsk-api`, systemd с жёсткими ограничениями, секреты вне репозитория.

## Остаточные риски (приняты)

* `FileProvider` Capacitor по умолчанию объявляет широкие пути (`external-path`/`cache-path` с `.`); провайдер не экспортируется (`exported=false`) и выдаёт доступ только по явным разрешениям, поэтому риск низкий. Сужение требует проверки съёмки камерой в каждой версии Android.
* Релизная сборка без обфускации (`minifyEnabled false`): код читаем. Секретов в приложении нет (адрес сервера и публичная логика).
* Подписанные ссылки на файлы содержат токен в адресе (10 минут, привязка к сессии), поэтому попадают в журнал nginx; журнал доступен только администратору сервера.
* Резервные копии не шифруются (лежат на сервере; при выносе на внешний носитель защищайте канал и хранилище: в дампе хэши паролей и зашифрованные секреты 2FA).
* Зависимости: `react-router` (open redirect при недоверенных адресах — у нас только фиксированные пути), `exceljs → uuid`, `prisma CLI → deepmerge-ts` (только инструмент миграций). Обновление — мажорные версии, планово.
* Без HTTPS (тестовый стенд по `http`) не работают push, установка PWA и часть функций браузера; на боевом сервере HTTPS обязателен.

## Остаточные риски (приняты)

* По требованию заказчика пользователь не меняет пароль сам: выдавший пароль сотрудник знает его, пока пароль не перевыпустят. Смягчение: выдача пароля и сброс 2FA только в пределах своих прав, всё пишется в журнал, при включении 2FA прочие сессии завершаются.
* Повторное использование refresh-токена в первые 30 секунд после ротации не считается кражей (иначе параллельные вкладки выбивали бы сессию).
* Зависимости без изменений (см. третий аудит): `prisma` CLI → `deepmerge-ts`, `react-router` (open redirect при недоверенных адресах — у нас только фиксированные пути), `exceljs` → `uuid`.
